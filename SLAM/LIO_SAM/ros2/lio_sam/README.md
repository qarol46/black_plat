## [Цель](#оглавление)

Пакет трёхмерного картографирования и локализации по интегрированным данным LiDAR & IMU — **LIO-SAM**. Запускается как контейнеризированный сервис `lio-sam` в составе общего docker-compose стека платформы (см. [корневой README](/README.md)).

---

## [Структура проекта](#оглавление)

```bash
SLAM/LIO_SAM/
├── docker
│   └── Dockerfile          # Образ сервиса lio-sam
├── ros2
│   └── lio_sam/
│       ├── include
│       ├── launch
│       │   ├── run.launch.py    # Основной launch-файл
│       │   └── rviz.launch.py   # Запуск и визуализация
│       ├── msg
│       ├── src
│       ├── srv                  # Сервис сохранения карты (save_map)
│       ├── CMakeLists.txt
│       ├── package.xml
│       ├── LICENSE
│       ├── README.md            # <Вы находитесь здесь>
│       └── README_old.md        # Оригинальное описание (запуск без Docker)
```

Сервис `lio-sam` описан в корневом [`docker-compose.yaml`](/docker-compose.yaml) и наследует общие extension-блоки `x-env`, `x-vol`, `x-deploy` (переменные окружения, монтирование `data/`, `dds/`, X11-сокета, доступ к GPU).

## [Запуск](#оглавление)

### Запуск внутри контейнера
Запуск производится из корня репозитория `black_plat` — либо через `Makefile`, либо напрямую через `docker compose`. Перед первым запуском убедитесь, что переменная `ROOT_DIR` выставлена (см. [раздел "Сборка" в корневом README](/README.md#сборка)).

#### Через Makefile

```bash
# Собрать образ lio-sam
make build-lio-sam

# Запустить только lio-sam (в текущем терминале, с логами)
make up-lio-sam

# Запустить в фоне (без вывода логов)
make up-lio-sam LOG_MODE=false

# Остановить
make down-lio-sam

# Логи в реальном времени
make logs SERVICE=lio-sam

# Bash внутри контейнера
make shell SERVICE=lio-sam

# Статус контейнера
make ps
```

#### Через docker compose напрямую

```bash
docker compose build lio-sam
docker compose up lio-sam          # с логами в терминале
docker compose up -d lio-sam       # в фоне
docker compose stop lio-sam
docker compose logs -f lio-sam
docker compose exec lio-sam bash
```

### Особенности сервиса

- `network_mode: host` — контейнер использует сетевой стек хоста, отдельная настройка портов не требуется.
- `privileged: true` — необходим для корректного доступа к устройствам (LiDAR, IMU и т.д.), пробрасываемым через `/dev/*`.
- `restart: always` — контейнер автоматически перезапускается при падении.
- Используется `develop.watch`: изменения в `ros2/` (кроме `config/`) вызывают пересборку контейнера, изменения в `config/` — синхронизацию и рестарт без пересборки. Работает при запуске через `docker compose watch`.
- При остановке контейнера (`pre_stop`) автоматически, в течение 15 секунд (`stop_grace_period`), вызывается сервис сохранения карты в `/data/maps/new_map` — если сервис не успевает отработать за это время, карта не сохранится (см. также [раздел "Сохранение карты"](#сохранение-карты)).

### Запуск вне контейнера

```bash
. install/setup.bash
ros2 launch lio-sam run.launch.py
```

## [Настройка](#оглавление)

Раздел будет дополнен.

Самым важным параметром после названий топиков является положение IMU в системе координат LiDAR'a: `extrinsicTrans: [-0.154, 0.0, -0.251]`. При неверном значении работа алгоритма будет нарушена.

Файл параметров: `data/configs/slam/lio_sam/params.yaml` (монтируется в контейнер через общий volume `data/` → `/data`, см. `x-vol` в корневом `docker-compose.yaml`).

## [Сохранение карты](#оглавление)

Карта сохраняется автоматически при штатной остановке контейнера (`make down-lio-sam` / `docker compose stop lio-sam`) через `pre_stop`-хук.

Для ручного сохранения карты во время работы контейнера зайдите внутрь него и вызовите сервис:

```bash
docker exec -it lio-sam bash
```

Внутри контейнера:

```bash
source /opt/ros/humble/setup.bash
source /ros2_ws/install/setup.bash
ros2 service call /lio_sam/save_map lio_sam/srv/SaveMap "{resolution: 0.2, destination: /data/maps/service_LOAM}"
```
Сохранение карты при запуске вне контейнера выполняется теми же командами, что и внутри контейнера.

Путь назначения указывается относительно `/data` внутри контейнера — это смонтированная директория `data/` корня репозитория, поэтому сохранённая карта будет доступна на хосте по пути `data/maps/service_LOAM`.

При использовании `rqt_gui service_caller` также необходимо предварительно обновить окружение (`source ...`) внутри контейнера.

## [Зависимости](#оглавление)

Устанавливаются автоматически при сборке образа `lio-sam` (`docker/Dockerfile`). Со стороны хоста требуются только общие зависимости проекта: Docker Engine, NVIDIA Container Toolkit (при использовании GPU), `make` — см. [раздел "Зависимости и установка" в корневом README](/README.md#зависимости-и-установка).

При установке вне контейнера:

```bash
sudo apt install ros-<ros2-version>-perception-pcl \
  	   ros-<ros2-version>-pcl-msgs \
  	   ros-<ros2-version>-vision-opencv \
  	   ros-<ros2-version>-xacro

# Add GTSAM-PPA
sudo add-apt-repository ppa:borglab/gtsam-release-4.1
sudo apt install libgtsam-dev libgtsam-unstable-dev      
```
❕*Версия GTSAM для LIO-SAM может конфликтовать с версиями для других SLAM-алгоритмов при установке вне контейнера.*❕

## [Известные проблемы](#оглавление)

1. Не отображается облако точек строящейся карты или нет данных с IMU — перепроверьте подключение датчиков и убедитесь, что они запущены и корректно публикуют данные в ожидаемые топики.
2. Публикация TF (сломанное дерево или несколько источников TF) — необходимо убедиться, что не запущено других программных модулей, публикующих трансформации. Для выбора линка, относительно которого будет публиковаться одометрия методом LIO-SAM, необходимо выбрать соответствующий пункт в yaml-файле (PublishOdomToBase или PublishOdomToLidar). В случае публикации TF относительно лидара, для корректной работы необходимо сделать линк лидара корневым в URDF-модели. (Подробнее [тут](https://github.com/TixiaoShan/LIO-SAM/issues/519) [и тут](https://github.com/TixiaoShan/LIO-SAM/issues/482)).
3. Подбор матриц ковариации — можно осуществлять путём записи rosbag с данными лидара и IMU и использования пакета li-calib. При некорректном заполнении матриц возможна ошибка "Large velocity, reset imuPreintegration". [Решение тут](https://github.com/TixiaoShan/LIO-SAM/issues/220).
